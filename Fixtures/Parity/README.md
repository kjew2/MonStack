# Parity fixtures

Generated by `node web/tools/gen-parity.js` from the JS reference core (`web/sim.js` + `web/content.js`). Do not edit by hand.
Consumed by the C# sim tests and the wasm engine run: replay `steps` on the C# core and require every result to equal `expect`, in order, exactly.

## File schema

```
{
  "name": "fights",
  "content": "Content/content.json",   // content to load (repo-relative)
  "seedHex": "1a2b",                    // profile seed, hex, up to 16 digits: ulong.Parse(seedHex, HexNumber)
  "nowMs": 1767225600000,               // wall clock passed when creating the profile
  "emitHits": false,                    // call SetEmitHits(1) right after creation when true
  "steps": [ ... ],
  "expect": [ ... ]
}
```

Create the sim as `Sim.newProfile(content, {profileSeed, nowMs, profileId: "fixture"})` (applies the tutorial grants and first-day login).
Files are written with one step / one expect entry per line (the `steps` and `expect` arrays are line-aligned only loosely: use the schema, not line numbers).

## Steps

| step | effect | contributes to `expect` |
|---|---|---|
| `{"op":"advance","n":int}` | `advance(n)` | no |
| `{"op":"sync","nowMs":number}` | `syncWallClock(nowMs)` | no |
| `{"op":"state"}` | UiState snapshot (see below) | yes: the object |
| `{"op":"drain"}` | `drain()` | yes: the event array |
| `{"op":"drain","check":false}` | `drain()` but the result is NOT compared | no |
| `{"op":"query","name":s,"args":[...]}` | the `Sim` method / bridge query of that name | yes: its return value |
| `{"op":"cmd","name":s,"args":[...]}` | the command of that name | yes: its return value |

`expect` holds one entry per step marked "yes", in step order. Command results: object as returned by sim.js (`{ok,...}`); `buyStatLevelsMax` and `autoEquip` return a bare number; `debugGrantGold`, `debugGrantGems`, `debugSetStage`, `unequipHero` results are `null` for the first three (sim.js returns undefined) and `{"ok":true}` for `unequipHero`. `pull` results include every field (`ok,results:[{id,name,tier,isNew,levelBefore,levelAfter,shards,pity,forced}],paidWith`) or `{ok:false,reason}`.
Query notes: `consolidatedRates` is the exported function `consolidatedRates(content)` in sim.js (not a `Sim` method): `{expectedPulls,lplus,m,l}`. `pullPrice` returns `null` or `{with, gems?}`. `validate` returns an array of strings. Optional query arguments are always omitted (`args: []`), never `null`: in sim.js `statMult(null)` would mean 0, not "default".

## UiState

`sim.state` with `rng` removed and nothing else changed (no renaming, no BigInt). Fields as in `web/wasm/BRIDGE.md`. `heroes.owned` keys are sorted by id in fixtures; comparison is key-order-insensitive for objects, array order is significant.

## Numbers

Doubles are written with JavaScript's shortest round-trip form, never rounded; compare as IEEE doubles (bit-equal). Integers beyond 2^53 never occur. No NaN/Infinity occurs (the generator throws).

## Events

Exactly what `drain()` returns: objects with `type`, `tick`, plus the type's own fields, in emission order. `hit` events appear only in fixtures with `emitHits: true` (first-minute).
