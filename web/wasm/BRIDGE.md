# Engine bridge contract (browser UI <-> C# core)

The browser UI in `web/` plays through the C# `IdleRng.Sim` compiled to WebAssembly. `src/IdleRng.Web` is an **adapter** over `AccountOps`, `TrainingRun`, `ContentDb` and the account save in `IdleRng.Runtime`: it maps them onto the JSON shapes below and adds no game rules. Changes to the core stay in the core; this file changes only when the bridge does. (The idle game's bridge, `Init`/`Advance`/`State`/`Query`/`Cmd`, was removed with that game at `specs/13` T7.)

Build: `web/wasm/build.sh` (packs `Content/*.json` with `pack-content.js`, publishes `src/IdleRng.Web`, writes `web/wasm/dist/`). Test: `node web/wasm/test/run-trainer.js`, `node web/wasm/test/flows.js` and `node web/wasm/test/golden.js` (the golden check below). Republish the phone artifact: `web/wasm/publish-artifact.sh` (builds, then prints the Artifact publish call as JSON). The build writes `dist/build-info.json` (version, commit, dirty flag, date), which the page header shows as `vMAJOR.MINOR · commit` (`#build`, "dev" without it). MAJOR is the root `VERSION` file, bumped by hand; MINOR is the number of commits on main's first-parent line since `VERSION` last changed (one per merge), so it rises on its own.

`web/engine.js` is the loader: `IdleEngine.loadWasm(opts)` fetches `wasm/dist/_framework/dotnet.js`, starts the runtime and returns `{ host, contentPack }`; if loading fails it rejects with a message the UI shows (bundle not built, page opened as a file, or the load error). `web/run-engine.js` builds the facade on top.

## The bridge

The static class `IdleRng.Web.Engine` exposes the monster trainer (`specs/14`, `15`, `18`, `19`, `21`) through `src/IdleRng.Web/RunHost.cs`, which holds the player's `AccountState` and its active run. Every member is `[JSExport]`: strings, ints and doubles only, JSON text for structure, errors come back as `{"error":"..."}`, nothing throws across the boundary except `RunInit` (bad content).

```
RunInit(string contentJson) : void
RunContent() : string                          // JSON labels and tables, never changes in a session (below)
AccountNew(string seedHex) : string            // a new account (the starter species only, no shards); returns AccountView
AccountLoad(string saveText) : string          // AccountSave text -> account; {"error"} when damaged or from a newer schema; a run that no longer replays is dropped and the view carries "notice"
AccountSave() : string                         // AccountSave text (header line + JSON; the active run is its replay recipe)
AccountView() : string                         // account JSON (below)
AccountCmd(string name, string argsJson) : string
RunState() : string                            // the active run's state, or "null"
RunCmd(string name, string argsJson) : string  // result object; {"ok":false,"reason"} when the engine refuses
```

Commands are applied by the shared dispatcher `IdleRng.Sim.Account.AccountCommands` (`AccountCommand.Parse(name, args)` then `Apply`), the same one the server will run (`specs/27` section 4); the bridge only formats each result. Account commands (`AccountOps`): `startRun(species, books[], talentsOff[]?)` (`talentsOff`: the run's loadout, owned talents switched off; omitted = the saved one; `specs/18` section 4), `setLoadout(talentsOff[])` (saves the loadout the next run starts with; refused for an unknown talent or more legendaries on than `legendarySlots`), `finishRun(utcMs)` (pays shards, seals the Vault entry, checks achievements, adds the grade's Dungeon ticket pieces and rolls the vendor, returns `{shards, ticketPieces, ticketsEarned, entry, climb, booksReturned, achievements[{id, name, text, species|null, speciesName|null}]}`; `species` is set when that achievement unlocked it; `climb` is the gauntlet the monster just climbed, `{floorReached, cleared, killer|null, hash, floors[{floor, enemy, boss, won, ticks}]}`, for the wheel shown once (`specs/19` section 7): nothing replays it later), `buyOffer(vendorIndex)` (buys a post-run vendor offer, `{cost, talent}`; `specs/18` section 4), `rerollVendor` (replaces the unbought offers with a fresh roll, `{cost}`; refused with nothing to reroll or too few shards), `closeVendor` (the player left the vendor screen: the vendor and its unbought offers are gone; nothing to close is fine), `abandon` (pays and seals nothing; unused books return to the inventory), `dismantle(vaultIndex)` (removes that entry, `{refund}`; refused when locked), `lock(vaultIndex, bool)`, `debugGrantBook(id, n)`, `runTower(day, vaultIndices[])` (one Dungeon attempt, spending one ticket and paying every floor cleared, `specs/21` section 7: `{shards, ticketsLeft, floorReached, cleared, floorsCleared, hash, books[{floor, book, name}], firstClears[], floors[{floor, boss, name, marquee, won, ticks, vents, corruption, hash, phases[name], team[{dealt, taken, healed}]}], final}`, where `hash` is the floor's fight hash, `team` each team monster's damage dealt, damage taken (HP lost, after shields) and healing done on that floor in slot order (the damage chart) and `final` is the last floor's fight in the tower fight shape below), the read-only `towerFloor(day, vaultIndices[], floor)` (one floor's fight of that team's attempt on that day in the tower fight shape, for playback: it replays `TowerSim.Run` and logs only that floor, so it is the fight `runTower` fought, with the same `hash`; it pays and counts nothing; refused when the team does not reach the floor or an index is not in the Vault), the read-only `towerInfo(day)` (`{day, tickets, ticketsPerDay, ticketCap, ticketPieces, piecesPerTicket, clearedToday, clearedEver, lastDay, teamMax, floors[{floor, boss, name, element, marquee, level, phases[{kind, name, desc, enterHp}]}]}`; `web/run-engine.js` exposes the three, with `towerDay()` = the UTC day number from the device clock), `setRulebook(vaultIndex, text)` (sets that monster's gambit rulebook in rulebook text, `specs/28` sections 4.4 and 7; `""` clears it; refused for text that does not parse, more than `gambitSlots` rules, or an action that is not `basic` or one of the monster's active skills; the rulebook is used in every team mode, the Dungeon included, and each Vault `entry` carries it as `rulebook`), `runEndless(season, vaultIndices[])` (one free Endless Tower climb with exactly `teamSize` monsters, paying each floor new this season, `specs/28` sections 5 and 6: `{season, shards, floorReached, capped, floorsCleared, clearedSeason, clearedEver, climbs, hash, newFloors[], firstClears[], achievements[{id, name, text, species|null, speciesName|null}], floors[{floor, shape, shapeName, elite, won, ticks, vents, corruption, hash, phases[name], team[{dealt, taken, healed}]}]}` (`team` as in `runTower`); refused for a season before the last climb's) and the read-only `endlessInfo(season)` (`{season, lastSeason, climbs, clearedSeason, clearedEver, teamSize, gambitSlots, band, maxFloors, mutators[{id, name, kind, value, element|null, fromFloor}], floors[{floor, shape, shapeName, check, elite, level, mutators, shards, enemies[{id, name, element, role}]}]}`: the next `band` floors after the season's best, and the season's mutators up to them; `web/run-engine.js` exposes the three with `endlessSeason(day?)`, the UTC week from Monday 00:00 UTC). `runEndless` also returns `final`, the deciding (last) floor's fight in the **endless fight** shape below. The read-only `endlessFloor(season, vaultIndices[], floor)` is any floor's fight for that team in the endless fight shape (each floor is fought on its own, `EndlessSim.FightFloor`, so it is the fight the climb fought there, with the same `hash`; floors not reached can be fought too), and the read-only `endlessPreview(season, vaultIndices[], floor, rulebooks[])` the same floor with edited rulebooks: one rulebook text per team slot, `null` for the monster's saved one, each checked as `setRulebook` checks it (refused otherwise); it pays, counts and saves nothing (the editor's test, `specs/28` section 4.5). `web/run-engine.js` exposes both. The command `setName(text)` sets the display name the boards show (`specs/28` section 6.1; `""` clears it; refused with the reason for a name `DisplayName.Check` does not allow; returns `{ok, name}` with the name as stored, trimmed and with spaces folded, or null), and the read-only `endlessBoard(season, top?)` is the season board as the server core gives it (`EndlessBoard.ReadAsync`): `{season, total, local, name, fallbackName, nameMin, nameMax, top[{rank, name, floor, you}], you}` where `you` is the player's row or null, `name` their display name or null, and `fallbackName` what the board shows without one. Until the page syncs with the server (`specs/27` step 3) the board is the server core's `EndlessBoard` over memory, built for each read from this account only (`local: true`): the bridge puts the account's season best and name on it, as the server does after an accepted commit. `web/run-engine.js` exposes `endlessBoard` and `setName`. Each `endlessInfo` mutator also carries `desc`, its effect in words. An **endless fight** is the tower fight shape plus `{season, floor, shape, shapeName, check, elite, eliteName|null, name, mutators[{id, name, desc}]}` (`name` is the elite's name on an elite floor, else the shape's); each team unit carries `vault`, its slot's Vault index, and enemies are named (an elite's add as its add row plus `#n`). A rule firing is an action with `event: "gambit"` and `amount` the rule's index from 0, just before the action it chose. The content carries `gambits: {slots, conditions[{id, name, desc, value: "fraction"|"count"|null}], targets[{id, name, desc}], basic{id, name, desc}}`, the rulebook editor's vocabulary (strings `gambit.*`), and each Vault entry `skills[]`, the ids of the active skills a rulebook may name (tooltips under `skillTips`).
Run commands (`TrainingRun`): `drill(stat)` (tier, gain, new value, energy, injured, `injury` null or `{cycle, lost, back}` (`specs/14` section 4.1; `back` 0 = the run ran out), `shielded` (Second Wind prevented an injury), `free` (Momentum: it cost no energy), `echoStat` and `echoGain` (Echo Training: the other stat it echoed into and the points added, null and 0 without it), milestones), `rest`, `fight` (below; `sp` is a win's SP or, on a loss, Grudge Match's), `take(choice, slot)`, `discard`, `reroll` (Second Look: redraws the oldest offer, a milestone draft, from the generic trees of any stat; `specs/18` section 3), `spend(slot)`, `book(id)`.

`fight` returns `{won, rankBefore, rankAfter, sp, opponent, outcome, ticks, units[{id, side, hp, maxHp, shield, damage, crits, evades, skills[{name, kind, cooldown}], cd[]}], actionCount, actions[{actor, target, amount, crit, evaded, aoe, counter, graze, lucky, skill?, skillId?, kind?, event?, si, hp[], sh[], cd[]}]}`. `graze` marks a magical hit that rolled under the target's evade chance (reduced damage, no crit) and `lucky` a hit whose evade or crit a fortune reroll decided (`FightAction.Graze`, `Lucky`; `specs/16` section 5.3). `event` is set on a sim event instead of a skill use (`FightAction.Event`): a Dungeon event (`phase:<kind>`, `vent:<kind>`, `check_failed`, `channel_broken`, `channel_strike`; `specs/21` section 6) or, in any fight, a rule modifier's event (`rule:<id>`, `specs/16` section 6.2), for which `skill` is the rule's name and `amount` the HP plus shield it restored (0 for `double_turn_start`'s extra action). `opponent` is the ladder step fought (the shape of `RunState().ladder` entries below, without `beaten` and `current`). `units` is the fight's unit order (side A, then B); `skills` is a unit's skill list in AI order, passives included, and `cd` its cooldowns left at the end (own actions until ready, indexed like `skills`). Each action carries a snapshot the bridge reads from the live fight as the sim reports it (`BattleSim.Resolve`'s `onStart` hook, `specs/16` section 2): `hp` is every unit's HP after it (indexed like `units`), `sh` every unit's shield after it (same index; the UI draws it as a band on the HP bar, and a shield that times out between actions shows until the next one), `cd` the actor's cooldowns after it, and `si` the index in the actor's `skills` of the skill it used (matched by skill id, so an echo counts as that skill; -1 for basic attacks, counters and triggered effects not in its list). Before the first action every unit is at its `maxHp` and before its own first action every skill of a unit is ready. `actions` is capped at 400 of `actionCount`. The UI replays this log at a presentation-only pace (`FIGHT_STEP_MS` in `web/run.js`, a placeholder; 1x, 2x or Skip, kept in `localStorage['idle-rng-fight-speed']`) and computes nothing from it.

A **tower fight** (`runTower`'s `final`, `towerFloor`) is the `fight` shape (no rank fields) plus `{floor, boss, name, marquee, won, ticks, hash, entropyCap, corruption, corruptMax}` (`corruption` is the level at the end, `corruptMax` the level the time limit reaches, `BattleSim.CorruptionLevel`); each unit adds `name` (an add is named after its row, with `#n`), `add` (a split phase's add), and `entropy` and `vent` at the end. Its actions carry tower `event`s and three more snapshots: `en[]` every unit's entropy and `vent[]` every unit's next vent kind (`recoil`, `stun`, `enrage` or `convert`, from `BattleSim.NextVent`), both indexed like `units`, and `corruption`, the level at that action. A split phase's adds join mid-fight, so `hp`, `en` and `vent` are as long as the units present at that action: an index past their length is a unit not yet in the fight.

`RunContent()`: `{version, consts{runCycles, runAp, energyMax, fightEvery, statMax, treeSlots, drillEnergyCost, restEnergy, spPerCycle, spPerWin, superP, shardsPerCycle, shardsPerRank, vaultCap, vendorOffers, legendarySlots, injurySkipCycles, injuryRecoverEnergy}, stats[], milestones[], elements{id:{name,color}}, species[{id,name,element,base,growth,trees,chase[in-run, book-gated],book (the skill book its book-gated chase tree needs, or null),starter,unlock (null for the starter, else the achievement that unlocks it: {achievement,name,text})}], ranks[{id,name,letter,element,stats,pool[]}] (`stats` are the rank's budget, also the flat opponent of a legacy run; `pool` its `rankEnemies` ids), rankEnemies{id:{id,name,rank,letter,element,boss,stats,skills[{id,name,kind}]}} (every rank pool monster, `specs/14` section 5; `boss` = the top rank's), trees{id:{id,name,kind,nodes[{id,cost,kind,name,desc,last,stat,amount (stat and amount on growth and stat nodes only)}],boosts[{stat,growth,flat}] (the filler nodes summed per stat, first-seen order; the tree offer's summary),source (where the tree comes from, in words),species, bookGated and apexName (chase trees only); fuseA, fuseB and apexName (fusion trees); fusesInto and fusesWith (a tree that fuses, `specs/15` section 5.6),conditions[text],conditionTrees[treeId]}}, books{id:{name,tree}}, talents[{id,name,desc,effect,rarity,maxRank,legendary}] (`rarity` is the talent's vendor tier; `legendary` when it takes a legendary slot), achievements[{id,name,text,species|null}], rarities[{id,name,legendary}] (vendor tiers, commonest first), gauntlet{floors, bossEvery, enemies{id:{name,element,boss}}}, statInfo{id:{name,desc}}, nodeTips{nodeId:tip}, skillNode{skillId:nodeId}, skillTips{skillId:tip}, towerTips{key:{name,text}}}` (tooltips, below).

`AccountView()`: `{notice?, seed, name (the display name or null), runsStarted, shards, hasRun, owned[], achievements[{id,earned,current,target}], books{id:n}, talents[{id,rank}], talentsOff[] (the loadout the next run starts with: talent ids switched off, `specs/18` section 4), vendor (null, or {grade, rerolls, rerollPrice, canReroll, offers[{talent,rarity,bought,rank,price,maxed}]}: an offer adds one rank; `price` is what buying it now costs, `rarity` the talent's tier; `rerolls` the rerolls made this visit, `rerollPrice` the next one's price, `canReroll` whether a reroll would change anything), mods{drillCostMult,statFloorMult,startSp,restEnergyBonus,failChanceDelta,superChanceBonus,shardMult,momentumDrills,lossSp,specialistBonus,treeSlotBonus,injuryShields,lastCycleAp,milestoneMult,draftRerolls,injuryImmune,restEnergyMult,neverFail,glassCannonBonus,echoFrac} (the `RunModifiers` the next run starts with under that loadout, `specs/18` section 3), vaultCap, vaultOver, vault[{species,apex (chase tree id of its apex form, or null; `specs/15` section 5.3),name (the apex or species name),seed,grade,rank,end,cycles,fightsFought,fightsWon,hash,sealedUtcMs,locked,refund,stats,trees[{id,bought,fusedInto,rolled}],gauntlet}]}` (the replay log stays in the save, not the view). `vaultOver` is how many entries are above `vaultCap` (`startRun` is refused while it is above 0, `specs/18` section 7); `refund` is the shards dismantling that entry pays; a `vaultIndex` is the entry's position in `vault` (oldest first). `gauntlet` is `{floor, cleared, killer|null, killerName|null, title, label, hash}`, or null for an entry sealed before the gauntlet existed: `title` is the Legacy Title with `{killer}` filled (`GauntletSim.TitleText`), `label` the line the UI shows, "Floor 42: Professional Punching Bag" (a cleared tower: "All 100 floors: Tower Breaker").

`RunState()`: `{species, apex, name, seed, phase (training|awaitfight|finished), end, cycle, ap, energy, sp, rank, fightsFought, fightsWon, drills, rests, fightDue, drillCost (the next drill's: 0 while Momentum has a free drill), restEnergy (what a rest restores before the cap), freeDrills, shieldsLeft (Second Wind), rerollsLeft (Second Look), canReroll (whether `reroll` would be accepted now), mods (the run's `RunModifiers`, same shape as the account view's), milestoneAt[] (the value each `milestones` threshold is crossed at this run; Early Bloom lowers it), odds{fail,super,success,injury} (with the run's talents), stats, growth, opponent{rank,letter,id,name,element,boss,skills[],stats}, ladder[{rank,letter,id,name,element,boss,skills[],beaten,current}], slots[null|{tree,bought,rolled,absorbed[{tree,bought,rolled}]}] (absorbed: a fusion tree's parents), offers[{source (milestone|book|chase|fusion),stat,threshold,trees[],rolled[]}] (`rolled`: per tree, null or a rolled Awakening tree `{stat, capGrowth, nodes[], boosts[]}`, `specs/15` section 4.1, drawn instead of the content tree's `nodes` and `boosts`; each rolled node's `id` names its rolled content and it carries its tooltip as `tip`), books[], chase[{tree,open,unlocked,met[]}] (the run species' two chase trees, in-run then book-gated; `open` is false only for the in-run tree of a legacy run replayed unattuned, `specs/15` section 5.4), tally, milestonesHit[], injuries[{cycle, lost, back}], hash, nowTitle, statNow{id:text}}`; `opponent` also carries `nowTitle`, `statNow` and the element matchup of the two units' own elements: `elementDealt`, the damage multiplier on the monster's hits on it, and `elementTaken`, on its hits on the monster (`ContentDb.ElementMult`: `ELEMENT_STRONG_MULT`, `ELEMENT_WEAK_MULT` or 1; a skill with an element of its own is not counted; the fight intro, issue #126). `ladder` is the run's rank ladder (`specs/14` section 5), lowest rank first: the opponent rolled for each rank (`id` a `rankEnemies` id; null in a legacy run, whose opponent is the flat rank, named after it, with no skills), `skills` its skill ids, `beaten` when the monster won a fight at that rank (below its rank now, or a win at the top rank), `current` for the rank fought next; `opponent` is the current step. Odds, costs, growth, chase conditions and every label come from the C# side; the UI computes nothing.

**Tooltips** (`specs/16` section 9; drawn by `web/tooltips.js`). All text, built by `BattleText` from content strings and the battle formulas; the UI only lays it out.
- `statInfo[id]`: the stat's `name` and `desc` (what it does, constants filled in).
- `statNow[id]` and `nowTitle` on the run state: what the monster's current value does against the coming rank opponent ("Takes 68% of physical damage"), before buffs and passives; `opponent.statNow` and `opponent.nowTitle` are the same for the opponent against the monster.
- `nodeTips[nodeId]`: `{title, text, tags[], facts[[label, value]]}` for every tree node: a skill's effect, amount, damage type, element, target, duration, cooldown or trigger, AI condition and SP cost; a rule's description; for a filler node, what its stat does.
- `skillNode[skillId]`: the node that grants a skill, so a skill named in the fight log opens that node's tooltip.
- `skillTips[skillId]`: the tooltip of every skill a rank opponent uses, on its own (`BattleText.SkillTip`: no trigger or SP cost), same shape as `nodeTips`. `web/tooltips.js` opens it for the ref `mskill:<id>` (the ladder's and the fight card's skill tags, and the opponent's lines in the battle log), and for `skill:<id>` when no node grants the skill.
- `towerTips[key]`: Dungeon playback tips (`BattleText.TowerTips`, `specs/21` section 8): `entropy`, `vent.<kind>` for each vent kind, `corruption` and `phase.<kind>` for each boss phase kind.

`web/run-engine.js` wraps this (`RunEngine.create`) and keeps the whole save in `localStorage['idle-rng-account-v1']`. A save that does not load is kept aside under `idle-rng-account-v1-unloadable-<ms>` (the oldest and the two newest are kept, `specs/06` section 5).

## Golden check

`GoldenVectors() : string` (needs `RunInit`) is for the tests, not the UI: it runs every generator of the bot CLI's `golden` verb (`IdleRng.Bots.Golden.GoldenFiles.All`: battle, training-run, gauntlet, tower and endless vectors, `specs/09` section 3) on the loaded content and returns `{"files":[{"name","text"}]}`, the text each `golden/` file must hold. It reads nothing from the account and changes nothing. `web/wasm/test/golden.js` (in `check.sh`) calls it on a bare page and compares each `text` byte for byte with `golden/`, so a WebAssembly build that resolves a fight differently from .NET fails the check (`specs/08` section 10.1, issue #122). For it, `IdleRng.Web` references `IdleRng.Bots` as a library (`ValidateExecutableReferencesMatchSelfContained` off; its `Main` never runs in the browser), which adds about 130 KB raw to `dist/`.

## Not exposed yet

The core's command log, `StateHash` and `Replay` (`specs/03` section 1, `specs/10` section 6) are not exposed through the bridge yet; they become relevant once the web client talks to a certifier (`specs/10` section 4).
