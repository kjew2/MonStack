# Engine bridge contract (browser UI <-> C# core)

The browser UI in `web/` plays through the C# `IdleRng.Sim` compiled to WebAssembly. `src/IdleRng.Web` is an **adapter** over `AccountOps`, `TrainingRun`, `ContentDb` and the account save in `IdleRng.Runtime`: it maps them onto the JSON shapes below and adds no game rules. Changes to the core stay in the core; this file changes only when the bridge does. (The idle game's bridge, `Init`/`Advance`/`State`/`Query`/`Cmd`, was removed with that game at `specs/13` T7.)

Build: `web/wasm/build.sh` (packs `Content/*.json` with `pack-content.js`, publishes `src/IdleRng.Web`, writes `web/wasm/dist/`). Test: `node web/wasm/test/run-trainer.js` and `node web/wasm/test/flows.js`. Republish the phone artifact: `web/wasm/publish-artifact.sh` (builds, then prints the Artifact publish call as JSON). The build writes `dist/build-info.json` (commit, dirty flag, date), which the page header shows (`#build`, "dev" without it).

`web/engine.js` is the loader: `IdleEngine.loadWasm(opts)` fetches `wasm/dist/_framework/dotnet.js`, starts the runtime and returns `{ host, contentPack }`; if loading fails it rejects with a message the UI shows (bundle not built, page opened as a file, or the load error). `web/run-engine.js` builds the facade on top.

## The bridge

The static class `IdleRng.Web.Engine` exposes the monster trainer (`specs/14`, `15`, `18`, `19`, `21`) through `src/IdleRng.Web/RunHost.cs`, which holds the player's `AccountState` and its active run. Every member is `[JSExport]`: strings, ints and doubles only, JSON text for structure, errors come back as `{"error":"..."}`, nothing throws across the boundary except `RunInit` (bad content).

```
RunInit(string contentJson) : void
RunContent() : string                          // JSON labels and tables, never changes in a session (below)
AccountNew(string seedHex) : string            // a new account (the starter species only, no shards); returns AccountView
AccountLoad(string saveText) : string          // AccountSave text -> account; {"error"} when damaged or from a newer schema; a run that no longer replays is dropped and the view carries "notice"
AccountSave() : string                         // AccountSave text (header line + JSON; the active run is its replay recipe)
AccountView() : string                         // account JSON (below)
AccountCmd(string name, string argsJson) : string
RunState() : string                            // the active run's state, or "null"
RunCmd(string name, string argsJson) : string  // result object; {"ok":false,"reason"} when the engine refuses
```

Account commands (`AccountOps`): `startRun(species, books[], talentsOff[]?)` (`talentsOff`: the run's loadout, owned talents switched off; omitted = the saved one; `specs/18` section 4), `setLoadout(talentsOff[])` (saves the loadout the next run starts with; refused for an unknown talent or more legendaries on than `legendarySlots`), `finishRun(utcMs)` (pays shards, seals the Vault entry, checks achievements, adds the grade's Dungeon ticket pieces and rolls the vendor, returns `{shards, ticketPieces, ticketsEarned, entry, booksReturned, achievements[{id, name, text, species|null, speciesName|null}]}`; `species` is set when that achievement unlocked it), `buyOffer(vendorIndex)` (buys a post-run vendor offer, `{cost, talent, ranks}`; `specs/18` section 4), `rerollVendor` (replaces the unbought offers with a fresh roll, `{cost}`; refused with nothing to reroll or too few shards), `abandon` (pays and seals nothing; unused books return to the inventory), `dismantle(vaultIndex)` (removes that entry, `{refund}`; refused when locked), `lock(vaultIndex, bool)`, `debugGrantBook(id, n)`, `runTower(day, vaultIndices[])` (one Dungeon attempt, spending one ticket and paying every floor cleared, `specs/21` section 7: `{shards, ticketsLeft, floorReached, cleared, floorsCleared, hash, books[{floor, book, name}], firstClears[], floors[{floor, boss, name, marquee, won, ticks, vents, corruption, hash, phases[name]}], final}`, where `hash` is the floor's fight hash and `final` is the last floor's fight in the tower fight shape below), the read-only `towerFloor(day, vaultIndices[], floor)` (one floor's fight of that team's attempt on that day in the tower fight shape, for playback: it replays `TowerSim.Run` and logs only that floor, so it is the fight `runTower` fought, with the same `hash`; it pays and counts nothing; refused when the team does not reach the floor or an index is not in the Vault), the read-only `towerInfo(day)` (`{day, tickets, ticketsPerDay, ticketCap, ticketPieces, piecesPerTicket, clearedToday, clearedEver, lastDay, teamMax, floors[{floor, boss, name, element, marquee, level, phases[{kind, name, desc, enterHp}]}]}`; `web/run-engine.js` exposes the three, with `towerDay()` = the UTC day number from the device clock), and the read-only `gauntlet(vaultIndex)`: the floors that Vault entry fought, for the wheel (`specs/19` section 7), by replaying `GauntletSim.Run(c, entry.Fighter(c), entry.Seed)`: `{floorReached, cleared, killer|null, hash, floors[{floor, enemy, boss, won, ticks}]}`. `hash` equals the entry's `gauntlet.hash`; `web/run-engine.js` calls it as `run.gauntlet(i)`, without saving.
Run commands (`TrainingRun`): `drill(stat)` (tier, gain, new value, energy, injured, `injury` null or `{cycle, lost, back}` (`specs/14` section 4.1; `back` 0 = the run ran out), `shielded` (Second Wind prevented an injury), `free` (Momentum: it cost no energy), milestones), `rest`, `fight` (below; `sp` is a win's SP or, on a loss, Grudge Match's), `take(choice, slot)`, `discard`, `reroll` (Second Look: redraws the oldest offer, a milestone draft, from the generic trees of any stat; `specs/18` section 3), `spend(slot)`, `book(id)`.

`fight` returns `{won, rankBefore, rankAfter, sp, opponent, outcome, ticks, units[{id, side, hp, maxHp, damage, crits, evades, skills[{name, kind, cooldown}], cd[]}], actionCount, actions[{actor, target, amount, crit, evaded, aoe, counter, graze, lucky, skill?, skillId?, kind?, event?, si, hp[], cd[]}]}`. `graze` marks a magical hit that rolled under the target's evade chance (reduced damage, no crit) and `lucky` a hit whose evade or crit a fortune reroll decided (`FightAction.Graze`, `Lucky`; `specs/16` section 5.3). `event` is set on a sim event instead of a skill use (`FightAction.Event`): a Dungeon event (`phase:<kind>`, `vent:<kind>`, `check_failed`, `channel_broken`, `channel_strike`; `specs/21` section 6) or, in any fight, a rule modifier's event (`rule:<id>`, `specs/16` section 6.2), for which `skill` is the rule's name and `amount` the HP plus shield it restored (0 for `double_turn_start`'s extra action). `opponent` is the ladder step fought (the shape of `RunState().ladder` entries below, without `beaten` and `current`). `units` is the fight's unit order (side A, then B); `skills` is a unit's skill list in AI order, passives included, and `cd` its cooldowns left at the end (own actions until ready, indexed like `skills`). Each action carries a snapshot the bridge reads from the live fight as the sim reports it (`BattleSim.Resolve`'s `onStart` hook, `specs/16` section 2): `hp` is every unit's HP after it (indexed like `units`), `cd` the actor's cooldowns after it, and `si` the index in the actor's `skills` of the skill it used (matched by skill id, so an echo counts as that skill; -1 for basic attacks, counters and triggered effects not in its list). Before the first action every unit is at its `maxHp` and before its own first action every skill of a unit is ready. `actions` is capped at 400 of `actionCount`. The UI replays this log at a presentation-only pace (`FIGHT_STEP_MS` in `web/run.js`, a placeholder; 1x, 2x or Skip, kept in `localStorage['idle-rng-fight-speed']`) and computes nothing from it.

A **tower fight** (`runTower`'s `final`, `towerFloor`) is the `fight` shape (no rank fields) plus `{floor, boss, name, marquee, won, ticks, hash, entropyCap, corruption, corruptMax}` (`corruption` is the level at the end, `corruptMax` the level the time limit reaches, `BattleSim.CorruptionLevel`); each unit adds `name` (an add is named after its row, with `#n`), `add` (a split phase's add), and `entropy` and `vent` at the end. Its actions carry tower `event`s and three more snapshots: `en[]` every unit's entropy and `vent[]` every unit's next vent kind (`recoil`, `stun`, `enrage` or `convert`, from `BattleSim.NextVent`), both indexed like `units`, and `corruption`, the level at that action. A split phase's adds join mid-fight, so `hp`, `en` and `vent` are as long as the units present at that action: an index past their length is a unit not yet in the fight.

`RunContent()`: `{version, consts{runCycles, runAp, energyMax, fightEvery, statMax, treeSlots, drillEnergyCost, restEnergy, spPerCycle, spPerWin, superP, shardsPerCycle, shardsPerRank, vaultCap, vendorOffers, legendarySlots, injurySkipCycles, injuryRecoverEnergy}, stats[], milestones[], elements{id:{name,color}}, species[{id,name,element,base,growth,trees,chase[in-run, book-gated],book (the skill book its book-gated chase tree needs, or null),starter,unlock (null for the starter, else the achievement that unlocks it: {achievement,name,text})}], ranks[{id,name,letter,element,stats,pool[]}] (`stats` are the rank's budget, also the flat opponent of a legacy run; `pool` its `rankEnemies` ids), rankEnemies{id:{id,name,rank,letter,element,boss,stats,skills[{id,name,kind}]}} (every rank pool monster, `specs/14` section 5; `boss` = the top rank's), trees{id:{id,name,kind,nodes[{id,cost,kind,name,desc,last,stat,amount (stat and amount on growth and stat nodes only)}],boosts[{stat,growth,flat}] (the filler nodes summed per stat, first-seen order; the tree offer's summary),source (where the tree comes from, in words),species, bookGated and apexName (chase trees only); fuseA, fuseB and apexName (fusion trees); fusesInto and fusesWith (a tree that fuses, `specs/15` section 5.6),conditions[text],conditionTrees[treeId]}}, books{id:{name,tree}}, talents[{id,name,desc,effect,rarity,maxRank,legendary}] (`rarity` is the talent's vendor tier; `legendary` when it takes a legendary slot), achievements[{id,name,text,species|null}], rarities[{id,name,legendary}] (vendor tiers, commonest first), gauntlet{floors, bossEvery, enemies{id:{name,element,boss}}}, statInfo{id:{name,desc}}, nodeTips{nodeId:tip}, skillNode{skillId:nodeId}, skillTips{skillId:tip}, towerTips{key:{name,text}}}` (tooltips, below).

`AccountView()`: `{notice?, seed, runsStarted, shards, hasRun, owned[], achievements[{id,earned,current,target}], books{id:n}, talents[{id,rank}], talentsOff[] (the loadout the next run starts with: talent ids switched off, `specs/18` section 4), vendor (null, or {grade, rerolls, rerollPrice, canReroll, offers[{talent,rarity,bought,rank,price,maxed}]}: an offer adds one rank; `price` is what buying it now costs, `rarity` the talent's tier; `rerolls` the rerolls made this visit, `rerollPrice` the next one's price, `canReroll` whether a reroll would change anything), mods{drillCostMult,statFloorMult,chaseChance,startSp,restEnergyBonus,failChanceDelta,superChanceBonus,shardMult,momentumDrills,lossSp,specialistBonus,treeSlotBonus,injuryShields,lastCycleAp,milestoneMult,draftRerolls} (the `RunModifiers` the next run starts with under that loadout, `specs/18` section 3), vaultCap, vaultOver, vault[{species,apex (chase tree id of its apex form, or null; `specs/15` section 5.3),name (the apex or species name),seed,grade,rank,end,cycles,fightsFought,fightsWon,hash,sealedUtcMs,locked,refund,stats,trees[{id,bought,fusedInto}],gauntlet}]}` (the replay log stays in the save, not the view). `vaultOver` is how many entries are above `vaultCap` (`startRun` is refused while it is above 0, `specs/18` section 7); `refund` is the shards dismantling that entry pays; a `vaultIndex` is the entry's position in `vault` (oldest first). `gauntlet` is `{floor, cleared, killer|null, killerName|null, title, label, hash}`, or null for an entry sealed before the gauntlet existed: `title` is the Legacy Title with `{killer}` filled (`GauntletSim.TitleText`), `label` the line the UI shows, "Floor 42: Professional Punching Bag" (a cleared tower: "All 100 floors: Tower Breaker").

`RunState()`: `{species, apex, name, seed, phase (training|awaitfight|finished), end, cycle, ap, energy, sp, rank, fightsFought, fightsWon, drills, rests, fightDue, drillCost (the next drill's: 0 while Momentum has a free drill), restEnergy (what a rest restores before the cap), freeDrills, shieldsLeft (Second Wind), rerollsLeft (Second Look), canReroll (whether `reroll` would be accepted now), mods (the run's `RunModifiers`, same shape as the account view's), milestoneAt[] (the value each `milestones` threshold is crossed at this run; Early Bloom lowers it), odds{fail,super,success,injury} (with the run's talents), stats, growth, opponent{rank,letter,id,name,element,boss,skills[],stats}, ladder[{rank,letter,id,name,element,boss,skills[],beaten,current}], slots[null|{tree,bought,absorbed[{tree,bought}]}] (absorbed: a fusion tree's parents), offers[{source (milestone|book|chase|fusion),stat,threshold,trees[]}], books[], chase[{tree,open,unlocked,met[]}] (the run species' two chase trees, in-run then book-gated; `open` is false for an in-run tree the run is not attuned to, `specs/15` section 5.4), tally, milestonesHit[], injuries[{cycle, lost, back}], hash, nowTitle, statNow{id:text}}`; `opponent` also carries `nowTitle` and `statNow`. `ladder` is the run's rank ladder (`specs/14` section 5), lowest rank first: the opponent rolled for each rank (`id` a `rankEnemies` id; null in a legacy run, whose opponent is the flat rank, named after it, with no skills), `skills` its skill ids, `beaten` when the monster won a fight at that rank (below its rank now, or a win at the top rank), `current` for the rank fought next; `opponent` is the current step. Odds, costs, growth, chase conditions and every label come from the C# side; the UI computes nothing.

**Tooltips** (`specs/16` section 9; drawn by `web/tooltips.js`). All text, built by `BattleText` from content strings and the battle formulas; the UI only lays it out.
- `statInfo[id]`: the stat's `name` and `desc` (what it does, constants filled in).
- `statNow[id]` and `nowTitle` on the run state: what the monster's current value does against the coming rank opponent ("Takes 68% of physical damage"), before buffs and passives; `opponent.statNow` and `opponent.nowTitle` are the same for the opponent against the monster.
- `nodeTips[nodeId]`: `{title, text, tags[], facts[[label, value]]}` for every tree node: a skill's effect, amount, damage type, element, target, duration, cooldown or trigger, AI condition and SP cost; a rule's description; for a filler node, what its stat does.
- `skillNode[skillId]`: the node that grants a skill, so a skill named in the fight log opens that node's tooltip.
- `skillTips[skillId]`: the tooltip of every skill a rank opponent uses, on its own (`BattleText.SkillTip`: no trigger or SP cost), same shape as `nodeTips`. `web/tooltips.js` opens it for the ref `mskill:<id>` (the ladder's and the fight card's skill tags, and the opponent's lines in the battle log), and for `skill:<id>` when no node grants the skill.
- `towerTips[key]`: Dungeon playback tips (`BattleText.TowerTips`, `specs/21` section 8): `entropy`, `vent.<kind>` for each vent kind, `corruption` and `phase.<kind>` for each boss phase kind.

`web/run-engine.js` wraps this (`RunEngine.create`) and keeps the whole save in `localStorage['idle-rng-account-v1']`. A save that does not load is kept aside under `idle-rng-account-v1-unloadable-<ms>` (the oldest and the two newest are kept, `specs/06` section 5).

## Not exposed yet

The core's command log, `StateHash` and `Replay` (`specs/03` section 1, `specs/10` section 6) are not exposed through the bridge yet; they become relevant once the web client talks to a certifier (`specs/10` section 4).
